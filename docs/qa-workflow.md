# Internal QA and Bug Bash Workflow

Internal QA is a first-class workflow in this workspace.

## QA scenarios vs research tasks

QA scenarios validate product behavior. Research tasks observe user behavior.

QA scenario example:

```text
Assign a tag to a Private Registry Module
```

Research task example:

```text
You need to make sure only approved modules are used in production. Show me how you would set that up.
```

## QA tracker outputs

The improved QA tracker should support:

- scenarios,
- dependencies,
- testers,
- status,
- bug/friction/improvement issue rows,
- evidence links,
- failed scenario to bug linkage,
- release-readiness summary.

## Engineering-authored style

Scenario wording should follow the original RAUC bug tracker pattern: concise, functional, and tester-oriented. Do not convert it into generic UX research prose.
